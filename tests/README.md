# tests\ - checks of the running lab

Every check that was used to verify the lab is here as a script, so you can see exactly
what was tested and run it again. Run them from the project folder, in PowerShell; they
need a deployed lab (OpenBao, Keycloak, Matrix) unless noted. No test prints a secret.

```powershell
.\tests\Invoke-LabTests.ps1                          # all tests that change nothing
.\tests\Invoke-LabTests.ps1 -Name Test-LabCertificates
.\tests\Test-LabCertificates.ps1                     # or one test directly
```

| Test | What it checks | Changes something? |
|---|---|---|
| `Test-LabCertificates.ps1` | every HTTPS endpoint: issued by the right CA (root or current intermediate, by key identifier), valid for more than 30 days, trusted by Windows including the revocation check | no |
| `Test-LabTlsPin.ps1` | the PC's OpenBao calls are pinned to the lab root; other hosts keep Windows' validation; a foreign chain is refused for the pinned host | no (one HTTPS request to www.microsoft.com as the foreign chain) |
| `Test-LabPasswordHash.ps1` | the firewall's password hashing over stdin gives exactly the hash of the command-line form (dummy value, also with a BOM-writing console) | no, local only |
| `Test-LabRetiredDpapi.ps1` | DPAPI secrets in `keys\openbao-retired-*` can be read under their new names | no (a temporary copy, deleted again) |
| `Test-LabRunToken.ps1` | a run token: policies, at most 2 hours, bound to ansible-control, orphan, temp files on tmpfs, revoked and cleaned up after the run (`remote\run-token-check.sh` runs on ansible-control) | no |
| `Test-LabSecretCreation.ps1` | creating a missing secret: generated by OpenBao, stored once, not stored under `--check`, read (not re-created) on the next run (`remote\secret-creation.yml`) | a throwaway secret `lab/keycloak/test-generated`, deleted again |
| `Test-LabFirewallRender.ps1` | the firewall's build path (secrets, GUI certificate from the root, config.xml, seed ISO) into a temporary folder | the root signs one extra test certificate; the temporary folder is deleted |
| `Test-LabRecoveryLogin.ps1` | the break-glass login (AppRole `recovery`) and the issuing of new PC logins, as `New-LabRecoveryKit.ps1 -Recover` does | **yes**: new pc-admin/pc-deploy logins, and an existing recovery kit's break-glass login stops working (then `New-LabRecoveryKit.ps1 -Renew`); asks first; only with `-IncludeStateChanging` |

Files:

- `LabTest.ps1` - shared helpers (one PASS/FAIL line per check, a summary, the exit code;
  copying `remote\*` to `/tmp/lab-tests` on ansible-control and removing it again)
- `remote\` - the scripts the tests run on ansible-control

The deployment scripts check themselves as well (for example `Deploy-LabMatrix.ps1`: ACME
certificates, MDAD's self-check, the login path to Keycloak); these tests cover what the
deployments do not.
